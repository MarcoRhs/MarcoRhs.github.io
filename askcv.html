Architecture decisions

Choose the system the problem needs.

A small professional profile has different requirements from ManeMap's contextual assistant. AskCV uses the full curated CV directly, with no vector retrieval or autonomous tools.

Knowledge

One reviewed record.

The Markdown CV generates a TypeScript constant included in the system prompt. This makes factual updates reviewable and avoids retrieval ranking for a corpus that fits in context. The tradeoff is that changes require regeneration and deployment.

Conversation

Questions remain untrusted.

The server serializes the current question and earlier questions as untrusted JSON. Previous assistant answers are not replayed. That preserves follow-up context without treating client-supplied assistant turns or fake CV additions as authoritative.

Output

Validate the contract.

The server accepts only a completed response with known source labels. It rejects truncated answers and invalid labels. This validates response structure; it cannot prove that every sentence is supported by the cited section.

Request path

Browser to model, through explicit boundaries.

The browser submits a question. The Edge Function controls admission, builds the model request and validates its response. Database operations belong to the application; the model has no database access.

  1. 01 · PARSE

    Bound the input.

    Reject invalid JSON and empty questions. Limit the body to 8,000 UTF-8 bytes and the question to 600 JavaScript string units. Keep at most four earlier questions, with 600 units combined.

  2. 02 · ADMIT

    Check request allowance.

    Database counters apply configured limits of 15 requests per IP bucket and 1,000 globally per UTC day. The function uses a salted IP hash. Shared connections and distributed traffic remain limitations.

  3. 03 · GENERATE

    Constrain the task.

    Gemini receives the reviewed CV, fixed rules and untrusted questions. A server-side timeout bounds the upstream wait. The prompt asks for supported facts, explicit gaps and answers in English, German or Spanish.

  4. 04 · VALIDATE

    Check completion and source.

    Require a completed answer and a final source line with recognized section names. Normalize a trailing period before checking labels. Reject missing, duplicated or invented source labels.

  5. 05 · DISPLAY

    Render text safely.

    The interface formats supported emphasis and lists without inserting model output as arbitrary HTML. Defined error states explain unavailable service, invalid responses and exhausted request allowances.

Historical evaluation · 2 October 2026

Tests that changed the implementation.

The published record reports 31/31 offline regression checks after the final formatting refinement, using Gemini 2.5 Flash. Checks used pattern matching and manual inspection of sensitive answers. This is a dated result, not a 100% accuracy claim or a fresh test of today's deployment.

Citation contract

Valid answers were rejected.

A role-fit answer correctly cited six CV sections, but the server allowed only five. The cap was aligned with the allowed source set. A separate check exposed a valid source label with a sentence-ending period; normalization now handles that presentation difference.

Unsupported claims

Refusal needed its own test.

Forged history and fake credentials probe whether visitor text can overwrite the CV. A response rejected a fabricated claim but omitted the required “not in CV” label. Prompt clarification and repeated checks addressed the missing citation behavior.

Boundary and presentation

Real inputs exposed gaps.

Live boundary probes covered malformed JSON, long questions, oversized UTF-8 bodies and foreign browser origins. Visitor feedback also exposed visible Markdown and collapsed lists; rendering was updated without accepting arbitrary model-generated HTML.

Threat model and limits

Controls have a job and a boundary.

Useful hardening starts with specifying what each control actually does. Important facts should still be checked against the CV and discussed directly with me.

Factuality

Labels are not entailment.

A permitted source label confirms that a section exists. It does not verify every statement above it. Model answers can still omit facts, misinterpret requirements or make unsupported claims. The evaluation probes defined cases rather than proving universal correctness.

Abuse and cost

Limits reduce exposure.

Origin checks constrain browser callers, but non-browser clients can omit Origin. Rate counters are the main admission control and are not an identity or anti-bot system. Some failed requests are refunded, so the counters are not a strict monetary spending cap.

Data and operations

Keep secrets server-side.

Provider credentials and database service access remain in the function. The application logs questions and answers under its published privacy policy; users should avoid sensitive information. Shared infrastructure and deployed settings remain operational responsibilities.

What this demonstrates

From model call to usable service.

I designed and built the public assistant as part of this portfolio, using AI-assisted implementation and review. It demonstrates practical work with request contracts, prompt boundaries, application controls, failure handling, evaluation and the interface a customer sees.

These skills are useful for bounded internal assistants, customer-facing AI features and implementation projects where the source of truth and acceptable behavior must be explicit. AskCV is a small application; it is not evidence of model training or large-scale ML infrastructure.

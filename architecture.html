Technical deep dive

How ManeMap and Milo are actually built.

ManeMap is a Kotlin / Compose Multiplatform app on iOS and Android with a Supabase backend. Milo combines retrieval, live horse context and layered safety controls before a response reaches the owner.

Request path

From question to guarded answer.

The safety decision starts before generation and continues after it. Retrieval is one part of the system, rather than the entire system.

  1. 01 · CLASSIFY

    Assess the risk first.

    Explicit emergency patterns catch known high-risk language. A second, lightweight model classifier checks symptom descriptions that do not use clinical terms.

  2. 02 · RETRIEVE

    Find relevant evidence.

    The question becomes a 768-dimension embedding and is matched with pgvector against the bilingual veterinary knowledge base.

  3. 03 · ASSEMBLE

    Add the horse context.

    Retrieved passages are combined with the active horse profile, medical and care data, recent training and current weather when available.

  4. 04 · GENERATE

    Answer inside constraints.

    Gemini receives the assembled context and response rules, including the ban on diagnosis, medication instructions and invented personal data.

  5. 05 · SANITISE

    Check the output.

    The server removes leaked internal labels and unsafe medication detail, adds a safe vet redirect when needed, then returns the cleaned response.

Architecture decisions

Why this stack fits the product.

Each choice reduces operational complexity or gives me tighter control over a user-facing risk.

Client

Kotlin / Compose Multiplatform

A shared codebase ships to both stores while keeping the app under direct product and engineering ownership. It replaced the first React Native version managed with an external team.

Data and retrieval

Supabase + pgvector

PostgreSQL, authentication, row-level access rules, serverless orchestration and vector retrieval stay in one backend stack, avoiding another service to operate.

Model layer

Gemini with explicit controls

The model handles multilingual generation and classification. Deterministic checks, constrained context and regression tests carry the product requirements around it.

Safety design

Controls at three points.

Health guidance can fail through missed urgency, unsafe wording or leaked internal detail. The pipeline addresses each failure at a different stage.

Before generation

Emergency detection

Rules cover high-precision signals; the second classifier covers paraphrases and symptom descriptions. Educational questions are separated from active incidents.

→
During generation

Response constraints

The prompt sets the response mode and blocks definitive diagnoses, prescribed medication detail and unrelated financial context in health situations.

→
After generation

Output sanitisation

Server-side cleaning removes internal mode labels and named medication content before the app receives the response.

Verification

What I test and observe.

The public claims on this site come from systems and checks that exist in the working products.

Regression suite

Critical behaviour before release.

Tests cover emergency detection, retrieval quality and context retention so prompt or model changes do not silently alter the highest-risk paths.

Observability

Timing by pipeline stage.

Embedding, retrieval and model stages emit timing data, which makes slow paths visible before optimisation work begins.

Public assistant

A separate grounded system.

AskCV has no tools or private data access. It validates input and output server-side, enforces source labels and is regression-tested for false claims and prompt injection.
